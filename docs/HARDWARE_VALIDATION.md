# Проверка в MasterSCADA 4D: что сделано без человека и что остаётся владельцу

## 1. Что проверено на машине автора без GUI

Установка: MasterSCADA 4D 1.3.10 Demo (1.3.10.35699, сборка `1.3.10_20261001.1`) с официального FTP ОВЕН
(`ftp.owen.ru/MasterSCADA_4D`), каталог `C:\Program Files\MPSSoft\MasterSCADA 4D 1.3\`.

| Что | Как | Итог |
|---|---|---|
| Тело `DoAction()` компилируется против настоящей объектной модели | `python tools/csc_check.py out/<имя> --real`: csc C# 5 + `bin/MasterSCADA.Scripts.Model.dll` 1.3.10, `using MasterSCADA.Scheme.Types;` (тест `tests/unit/test_csharp.py::test_real_model_compile`, маркер `ms4d`) | собрано без ошибок (корпус УДР-1) |
| Снимок API со страниц справки совпадает с поставкой | `python tools/ms4d_check.py`: 156 имён свойств и методов снимка против `bin/MasterSCADA.Scripts.Model.xml` (XML-документация из поставки, без декомпиляции) | 156 из 156 есть; члены модели, которыми пользуется скрипт (10), — все; `WriteConsole` — метод среды скриптов из примеров справки, в документации модели его нет |
| Скрипт строит ожидаемое дерево | тот же `BuildProject.cs` против макета API (`csharp/Stub`, сгенерирован из снимка) и модели-записи `FakeRunner` → `tree.json` = `expected-tree.json` = задачи и программы проекта | совпало (csc C# 5 и dotnet SDK 8) |
| XML импорта валиден | XSD TC6 2.01 (plcopen.org, SHA-256 `591b92ba…e20f`) после подмены namespace | валиден (тест, в CI обязателен) |

Автоматизация импорта и «Проверить» без GUI не найдена: в `bin/` — `ms4d.exe` (среда разработки) и
`Opc.Ua.CertificateGenerator.exe`; ключи командной строки для импорта, проверки или запуска скрипта справка 1.3.10 не
описывает; скрипты C# выполняются только из среды разработки (`HW:script_c`), объект `RootItemModel` создаёт среда.
Формат проекта закрыт, EULA п. 5.3 запрещает обратную разработку (`HW:licenzionnaya_politika`) — файлы проекта
cds2ms не пишет и не читает. Поэтому импорт, проверка, эмуляция и запуск скрипта — шаги владельца ниже.

**Нельзя говорить** «проверено в MasterSCADA», «импортируется», «совместимо с MasterPLC», пока шаги 2–5 не выполнены.
**Можно:** «XML валиден по XSD TC6 2.01; скрипт компилируется против объектной модели 1.3.10 и макета документированного
API; понижение сверено с CODESYS Control Win (кроме IL)».

## 2. Подготовка (один раз)

1. Среда разработки MasterSCADA 4D 1.3.10 (нужны права администратора, .NET SDK — `HW:ustanovka_sredw_razrabotki_masterscada_4d`),
   регистрация демо. Демо-рантайм работает 1 час — пробы исполнения (раздел 4) уложить в одну сессию.
2. `cds2ms migrate <проект CODESYS> --out out/<имя> --node <имя узла ПЛК>` либо готовый комплект `probe/` из репозитория.
3. Таблица результатов — `probe/RESULTS.csv` (столбцы семейства: `probe_id, construct, file, expected, observed, ide,
   ide_version, date, notes`); `observed` = `ok`, `error:<текст дословно>`, `value:<значение>`, `place:<путь в дереве>`
   или `not-run`.

## 3. Импорт и «Проверить» (≈ 75 мин)

| Шаг | Действие | Ожидаемый результат | Мин |
|---|---|---|---|
| P-IMP-01…07 | узел ПЛК → «Импортирование PLCOpenXML» (пункт меню — дословно со страницы `HW:-plcopenxml`, записать, как он назван в среде) → файлы `probe/import/*.xml`, каждый в новый проект | ФБ и функции — в локальной библиотеке, программы и глобальные — в узле; записать, куда легли глобальные, задачи, что с addData (P-IMP-05) | 35 |
| P-ST-01…08 | импорт `probe/dialect/P-ST.xml`, затем «Проверить» **проект целиком** (проверка одной программы даёт ложное «Неизвестная переменная» на глобальных — `HW:globalnye_peremennye`) | ошибки — дословно по POU: `var_inout`, CASE по ENUM, `EN` как имя входа, имена `a__b`/`local`/`end`, префикс `Локальная.`, ФБ в GVL и массивы ФБ, retain-атрибут, константы | 40 |

## 4. Исполнение в эмуляции (≈ 45 мин, одна сессия демо-RT)

Импорт `probe/runtime/P-RT.xml`, программы — в основную задачу узла (100 мс), эмуляция (`HW:emulyacia`). Значения
выходов P-RT-01…10 — в `value:` (ожидаемое для CODESYS указано в `RESULTS.csv`): переполнение INT, деление и MOD,
`REAL_TO_INT` на половинах, отрицательное TIME, `LEN` кириллицы, `DT` по умолчанию, выход за массив, FOR с `BY -1`,
TON 150 мс в задаче 100 мс (ожидаемо 200 мс — MS-EXEC-01), метод в режиме вызова. P-RT-11 (SFC N/P1 по циклам) и
P-RT-12 (TON на цепи Master LD при падении цепи) рисуются по `probe/runtime/SFC-recipe.md` и `LD-recipe.md`.
`PRG_ProbeDivZero` — последним: деление на ноль может остановить задачу.

## 5. Скрипт C# (≈ 20 мин)

По `probe/script/README.md`: импорт `udr1.plcopen.xml` → элемент «Скрипт» → `DoAction.body.cs` в `DoAction()` →
«Выполнить программу». P-CS-01 — дерево против `expected-tree.json`, повторный запуск ничего не дублирует; P-CS-02 —
направление `AddLink` и `DataSource`; P-CS-03 — «Экспорт ST текста» любой проверенной программы (образец формата
`.ST`); P-RT-13 — в эмуляции диспетчер `migTask_TaskFast` вызывает `PRG_Main`.

## 6. Обратная связь в проект

```
cds2ms profiles apply-probe probe/RESULTS.csv --write   # статусы профиля: «проверено вручную, дата, версия»
python -m pytest                                        # golden пересобираются отдельным коммитом
```

`ok`/`value:`/`place:` → `supported`, `error:` → `unsupported`; `not-run` не меняет ничего. Шаблон `.ST`
(`src/cds2ms/templates/st_file.txt`) правится по файлу P-CS-03.
